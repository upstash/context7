The hosted server can run an A/B test of the server instructions. With `CONTEXT7_INSTRUCTIONS_EXPERIMENT=remote`, it reads the test's config (experiment ID and control share, kept in context7app's Redis) once at startup from `/api/v2/mcp/instructions-experiment`, so a change needs only a restart. The control share of callers gets the previous instructions without `alwaysLoad`; the rest get the current ones. Without the config, or when the app cannot be reached, everyone gets the previous instructions. An HMAC of a stable caller identity (API key hash, JWT subject, token hash, or the client IP or IPv6 /64) with `MCP_CLIENT_IP_ASSERTION_KEY` keeps each caller in one arm. While the test runs, `tools/list` and `server/discover` are not shared across callers, API calls carry the arm as an encrypted `X-Context7-Instructions-Assertion`, and each instructions request is reported to context7app as an exposure. Stdio and self-hosted servers without the variable are not part of it.
