The Docs7 agents work from your GitHub repository and open pull requests for you to review. Open **Docs7**, choose a site, then select **Agent**.

The Agent tab has two cards:

- **Agents** shows each agent with its setting. Select **Edit** to turn agents on or off and change their settings. Every change saves at once; **Save** closes the rows.
- **Activity** lists every run of every agent, newest first. Filter by agent or state, and select a row to open its pull request on GitHub.

There are five agents:

- **Context7 Agent** turns reader questions and page feedback into docs fixes.
- **Build Fix Agent** fixes the errors and warnings that a build finds in your docs.
- **PR Review Agent** checks links, grammar, spelling, build health, and style in each docs pull request.
- **Code Watch Agent** updates the docs when a pull request merges in your code repositories.
- **Example Check Agent** runs the code examples in your docs against your services and fixes the ones that fail.

New sites start with every agent off. Each run counts toward the site's monthly agent allowance.

## Context7 Agent

The Context7 Agent works from suggestions that come from Context7's analysis of your indexed documentation. Choose **Daily** or **Weekly**.

Each run takes up to 10 waiting suggestions, checks each one against your repository, and edits only the configured docs path. If it makes changes, Docs7 opens one pull request. The agent does not start a new run while its last pull request is still open, and it does not take the same suggestion twice in a row.

## Build Fix Agent

The Build Fix Agent fixes the issues in your latest production build: page errors, broken internal links, unknown components, and source warnings. It needs Docs7 hosting.

Choose when it runs:

- **After each build** runs after every production build.
- **Daily** or **Weekly** runs on a schedule.

Each run takes up to 20 issues and opens one pull request. The agent does not start a new run while its last pull request is still open, and it skips the issues its last run already took.

## PR Review Agent

The PR Review Agent reviews each pull request that changes your docs path. It starts 5 minutes after the pull request's preview build finishes, so a quick follow-up push is reviewed only once. It posts its findings in the pull request's Docs7 summary, with inline comments on the changed lines.

Every review runs these checks:

| Check | What it reviews |
| --- | --- |
| **Broken links** | Broken internal links, dead external links, and links to missing headings in changed docs files. |
| **Build health issues** | New fixable issues introduced by the preview compared with production. Needs Docs7 hosting. |
| **Grammar and spelling** | Mistakes in text added or changed by the pull request. |
| **Docs conventions** | Changed pages against repository instructions and nearby documentation patterns. |

Choose what happens to the fixes:

- **Comment only** reports findings and does not change files.
- **Open a fix PR** opens a separate pull request with supported fixes.
- **Commit to branch** pushes supported fixes to the pull request branch. If the branch refuses the push, Docs7 opens a pull request against it instead.

Docs7 skips pull requests from forks and pull requests that do not change the configured docs path. It also skips commits created by the agent, which prevents review loops.

<Note>
Do not make **Docs7 PR Review** a required GitHub check. Fork pull requests do not receive that check.
</Note>

## Code Watch Agent

The Code Watch Agent keeps your docs in step with your code. When a pull request merges into the default branch of a repository you chose, the agent checks whether readers of your docs need a change. If they do, Docs7 opens one docs pull request that links to the merged pull request. Most merges change nothing that readers see, and then the agent opens nothing.

### Choose repositories

In the agent's row, open the repository menu and select up to 50 code repositories from the same GitHub account as your docs. The Docs7 GitHub App must have access to each one. Private repositories need Docs7 Pro. Then turn the agent on.

If your docs are in a folder of the same repository as your code, that repository is already selected and is first in the list.

### What the agent checks

The agent reads the merged change and looks for what readers can notice: added, removed, or renamed functions, methods, commands, options, parameters, defaults, limits, environment variables, configuration keys, and documented behavior. It then searches your docs for each one:

- If the docs already describe the change correctly, it changes nothing.
- If a page is now wrong, or a list of commands, methods, or options is missing the new item, it edits the docs and follows the structure and style of the nearby pages.

The agent edits only the configured docs path. The docs pull request goes through your normal review.

Docs7 does not run the agent for:

- pull requests opened by bots, such as release and dependency updates
- pull requests that change only tests, CI files, lockfiles, changesets, or changelogs
- pull requests that change only the docs, when the docs and code share a repository
- pull requests opened by Docs7 itself

For a pull request from a fork, the agent uses the merged code and ignores the pull request's title and description.

When a merge belongs with a docs pull request the agent already opened and that is still open, for example the same commands added to your JavaScript and Python SDKs, the agent adds its change to that pull request instead of opening another one.

Each checked pull request counts as one run.

## Example Check Agent

The Example Check Agent runs the TypeScript, JavaScript, and Python code examples of your docs against your services once a month. When an example fails because the example is wrong, the agent fixes it, runs it again, and adds the fix to a pull request. It needs Docs7 Pro.

### Add variables

In the agent's row, open the variables menu and add the environment variables your code examples read, for example `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN`. To add many at once, paste the contents of a `.env` file into any field: each line becomes one variable.

Docs7 encrypts every value and never shows it again. A URL goes into the sandbox where the code runs. Any other value is a secret and never enters the sandbox: Docs7 sends it as `Authorization: Bearer <value>` only in HTTPS requests to the host of the URL variable with the same prefix. For example, `UPSTASH_REDIS_REST_TOKEN` is sent to the host of `UPSTASH_REDIS_REST_URL`. The code in the sandbox reads a placeholder and can reach only package registries and the hosts of your URL variables.

<Warning>
Use test credentials. Code examples write and delete data, for example the keys in a Redis database.
</Warning>

### Checks

Turn the agent on. The first check starts within a day, and the next ones once a month. A check reads every page, in batches of about 100 code examples.

Each code example ends with one of these results:

- **Passed**: the example ran and did what the page says, including the documented output and responses.
- **Failed**: the example threw an error, or its result differs from the page. If the example has a mistake, such as a wrong method name, argument, value, expected output, import, or syntax, the agent fixes it and runs it again. If the example uses the API as documented and the SDK or service behaves differently, the agent reports this and does not change the page.
- **Skipped**: the example needs a service with no variable, connects over TCP (for example ioredis, node-redis, or redis-py with a `redis://` URL), is not a complete program, or is part of a whole framework app such as a Next.js route.

All fixes of a check go into one pull request. Its description lists every failed example of the check: the ones the agent fixed, and the ones it did not fix. A check with no fix opens no pull request. Activity shows each check as one row with its counts. Each batch counts as one run, so docs with 1,000 code examples use about 10 runs per check.

Each row shows the run's pull request and its state: **Running**, **Open**, **Merged**, **Closed**, **Passed**, **Commented**, **Committed**, **Failed**, or **No change**. A review row opens the pull request it reviewed, and a Code Watch row opens the merged pull request when the agent made no docs change.

## Safety and scope

Agent runs receive read access to the connected repository, and Code Watch runs receive read access to the code repository of the merged pull request as well. Example Check runs receive your variables; secret values stay outside the sandbox. The agent can inspect repository source to verify a documentation change, but trusted Docs7 code publishes the resulting files through GitHub.

Changes are limited to the configured docs path. When the docs path is the repository root, Docs7 still blocks common application paths, package manifests, lockfiles, `.github`, and `.git` from agent changes.
