---
title: Custom Domains
description: Serve your docs from your own domain or below a path on your main site
---

By default a site lives at `<owner>--<repo>.docs7.io`. You can attach one custom domain per site.

## Subdomains (recommended)

Add the domain in the site's dashboard settings, then create the CNAME record it shows at your DNS provider:

```
docs.example.com  CNAME  <target shown in the dashboard>
```

Docs7 issues a TLS certificate automatically (TLS 1.2+). The domain is live once both the hostname and the certificate show as active. Use **Check status** in the dashboard to refresh.

## Apex domains

`example.com` (no subdomain) works only if your DNS provider supports CNAME flattening (ALIAS/ANAME records), since a plain CNAME at the apex is not valid DNS. If yours doesn't, use a subdomain.

## Hosting below a path

Serve the docs at `example.com/docs` while the rest of the domain stays yours:

1. Set the custom domain **and** a custom path (like `/docs`) in the site settings.
2. Proxy that path from your own infrastructure to the Docs7 origin shown in the dashboard.

Links, assets, search, the sitemap, redirects, and Markdown exports are all generated with the path prefix. Path rules: 2–128 characters, starts with `/`, letters/digits/`._~/-`, no `//`, no trailing slash, no `..`. Platform-reserved first segments (`/api`, `/_next`, `/_assets`, `/llms.txt`, `/robots.txt`, `/sitemap.xml`, `/.well-known`, …) are refused. A custom path requires a custom domain.

## Rules and timing

- One domain per site, and a domain can belong to only one site anywhere.
- Domains under `docs7.io` cannot be claimed as custom domains.
- After removing a live domain, re-claiming it is blocked for ~2 minutes while edge caches drain. Moving a domain between sites can briefly serve the old site during that window.
- The `*.docs7.io` URL keeps working alongside the custom domain.
