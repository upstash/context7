---
title: Research Preview
description: Turn on experimental Context7 MCP tools, such as documentation feedback, upgrade guides and source code search
---

The research preview gives your agent experimental tools from the Context7 MCP server. It is off by default. Tools in the preview can change or be removed without notice.

The research preview currently adds three tools: [documentation feedback](#documentation-feedback), [upgrade guides](#upgrade-guides) and [source code search](#source-code-search).

## Turn it on

### Remote server

Add `research_preview=1` to the server URL:

```json
{
  "mcpServers": {
    "context7": {
      "type": "http",
      "url": "https://mcp.context7.com/mcp?research_preview=1",
      "headers": { "Authorization": "Bearer YOUR_API_KEY" }
    }
  }
}
```

With Claude Code:

```bash
claude mcp add --scope user --header "Authorization: Bearer YOUR_API_KEY" --transport http context7 "https://mcp.context7.com/mcp?research_preview=1"
```

The OAuth endpoint takes the same parameter: `https://mcp.context7.com/mcp/oauth?research_preview=1`.

### Local server

Pass `--research-preview`, or set `CONTEXT7_RESEARCH_PREVIEW=1`. This needs `@upstash/context7-mcp` 4.5.0 or later.

```json
{
  "mcpServers": {
    "context7": {
      "command": "npx",
      "args": ["-y", "@upstash/context7-mcp@latest", "--api-key", "YOUR_API_KEY", "--research-preview"]
    }
  }
}
```

Start a new session after you change the configuration, so that your client loads the new tools.

To turn the research preview off, remove the parameter, the flag or the variable.

## Documentation feedback

With the research preview on, the server lists a `submit-docs-feedback` tool, and its instructions ask the agent to call it once for each library after it answers with `query-docs`. The agent rates how well the documentation answered the question:

| Field | Description |
| --- | --- |
| `libraryId` | The library the feedback is about, such as `/vercel/next.js` |
| `query` | The `query-docs` query, optional |
| `score` | `0` (useless) to `5` (fully answered with correct, current code) |
| `issue` | What was wrong, only below 5: `missing`, `outdated`, `incorrect`, `irrelevant` or `other` |
| `comment` | What was missing, wrong or good, in one or two sentences |

You can also ask your agent to send your own comment, for example: "tell Context7 that the Next.js docs have no example for this". We use the feedback to find and fix gaps in library documentation.

### What is sent

The fields above, the name and version of your MCP client, and your account when you use an API key or OAuth. The tool does not send your code or files. For private libraries and for Enterprise teamspaces, Context7 does not store the query or the comment. Feedback about a library that your account cannot access is rejected.

### Codex

Codex asks for approval before each call to a tool that can send data, so it asks every time the agent sends feedback. In `codex exec` with `approval_policy = "never"`, the call fails. To allow only this tool, add it to `~/.codex/config.toml`:

```toml
[mcp_servers.context7.tools.submit-docs-feedback]
approval_mode = "approve"
```

## Upgrade guides

With the research preview on, the server also lists a `get-upgrade-guide` tool. The agent calls it when you upgrade a library, or ask what changed between two versions. It returns one guide with the prerequisites, codemods, breaking changes, deprecations, and behavior and config changes from the release notes, changelogs and migration guides of every release in between, each with its source. It adds the public API changes found in the source code of both versions, including those no note mentions.

| Field | Description |
| --- | --- |
| `libraryId` | The library, such as `/vercel/next.js` |
| `fromVersion` | The version you use now, such as `14.2.35` or `14`. A bare major means the oldest release of that line |
| `toVersion` | The version to upgrade to, such as `16`, optional. A bare major means the newest release of that line; without it, the latest major |
| `page` | The page of a long guide, optional, `1` by default |

A long guide comes in pages, each in full detail and sized for MCP clients. Page 1 starts with what is needed to migrate (the summary, prerequisites, codemods, breaking changes and deprecations); when that part is longer than one page, it continues on the next pages, and page 1 says so. After it come behavior and config changes and the API changes, which the agent fetches when it needs them.

The first request for a pair of versions can take a few minutes while Context7 prepares the guide; a guide is served only once it is complete. The tool then tells the agent when to call again. If a guide cannot be prepared, the tool says so and the agent uses `query-docs` instead. After a wait from minutes to a day, depending on why it failed, a new request prepares the guide again; the tool's answer says when to ask.

Guides are prepared for about 100 of the most used libraries. For any other library the tool answers that its guide is not prepared yet. The tool needs `@upstash/context7-mcp` 4.6.0 or later; reading the pages after the first needs 4.7.0 or later.

## Source code search

With the research preview on, the server also lists a `query-code` tool, and `resolve-library-id` marks the libraries whose source it can search with `Source code: searchable with query-code`. The agent uses it when the docs do not answer an exact question, such as a signature, a default value, an option name, or where an error message comes from. It searches and reads the library's source at the commit its docs describe.

| Field | Description |
| --- | --- |
| `libraryId` | A library built from a Git repository, such as `/colinhacks/zod`. `/websites/...` and `/llmstxt/...` libraries have no source |
| `operation` | `grep` (default), `definition`, `references`, `outline`, `read` or `list` |
| `pattern` | A regex for `grep`, or a symbol for `definition`, `references` and `read` |
| `version` | A git tag, such as `v3.24.2`, optional. Without it, the commit the docs were built from. A tag that is not a docs version is indexed on first use |

`grep` also takes ripgrep's options: `fixed_strings`, `ignore_case`, `glob`, `path`, `context`, `output_mode`, `head_limit` and `offset`. While a library's source is being indexed, the tool tells the agent to call again or answer from `query-docs`.

The tool needs `@upstash/context7-mcp` 4.6.0 or later.

Without the MCP server, the `ctx7 code` command gives the same search in a terminal, for example `npx ctx7@latest code /colinhacks/zod "safeExtend" --op definition`.
