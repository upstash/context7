---
title: Manage API Keys
description: Create and manage API keys for Context7 authentication
---

API keys authenticate your requests to Context7's documentation services. You can create one in the [Context7 dashboard](https://context7.com/dashboard).

## Managing API Keys

![API Keys card showing list of keys with details](/images/dashboard/api-keys-card.png)

### Creating API Keys

<Steps>
  <Step title="Open the create dialog">
    Click **Create API Key** in the API Keys card.
  </Step>
  <Step title="Name the key">
    Enter a name (optional but recommended). Descriptive names like "Cursor", "Claude", "VS Code", or "Devin Desktop" help you identify the key later.
  </Step>
  <Step title="Choose write access">
    Every key can read the teamspace settings and usage through the management API. Tick **Write access** for a key that must change the teamspace or read personal data, like members and visitor questions (see [below](#write-access)). Leave it off for keys that only fetch docs or read settings.
  </Step>
  <Step title="Copy the key immediately">
    Keys are shown only once for security. The format is `ctx7sk-**********************`.
  </Step>
  <Step title="Use the key">
    Use it in your requests or MCP configuration:

    ```bash
    curl "https://context7.com/api/v2/context?libraryId=/vercel/next.js&query=routing" \
      -H "Authorization: Bearer YOUR_API_KEY"
    ```
  </Step>
</Steps>

<Warning>Store your API key securely. You won't be able to see it again after creation.</Warning>

### Write access

The [Context7 Admin MCP](/howto/admin-mcp) and the [management API](/api-reference/teamspaces/list-teamspaces) (`/api/v2/teamspaces/*`) accept every API key, but a key is read-only there unless **Write access** was ticked when the key was created. A key reaches only its own teamspace.

A read-only key can read, with your role:

- the teamspace's libraries, rules and policies, and usage
- Docs7 and Ask site settings, builds and traffic totals

A key needs **Write access** to:

- read personal data: members and invitations, library requests, Ask questions, Docs7 reader searches, assistant questions and conversations, page feedback, feature requests, and the GitHub account behind a build
- change the teamspace: its members, libraries, rules and policies, spending limit, and Docs7 and Ask sites

![Create New API Key dialog with Write access ticked](/images/dashboard/api-key-write-access.png)

A read-only key gets `403` with the error `write_access_required` when it tries to make a change or read personal data. The teamspace invite link also needs write access, because the link lets anyone join. You cannot add write access to an existing key: create a new key with the box ticked. With the Admin MCP you can also sign in with OAuth and use no key.

### Revoking Keys

<Steps>
  <Step title="Delete the key">
    Click the delete button next to the key you no longer need.
  </Step>
  <Step title="Confirm deletion">
    Confirm in the modal. The key deactivates immediately — all requests using it will fail.
  </Step>
</Steps>

<Note>
  Revoking a key is permanent and cannot be undone. Update any applications using the key before
  revoking.
</Note>
