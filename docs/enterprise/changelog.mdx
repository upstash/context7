<Update label="2026-11-06" description="v2.0.0">

### Upgrade notes

- Back up the data volume before you upgrade. The first start runs a database migration automatically.
- The `latest` image tag now points to 2.0.0. To stay on 1.3.9, pin the image to `1` or `1.3`.
- Settings now have one page per section at `/settings/<section>`. Bookmarks to the old `?tab=` links redirect to the new pages.
- The settings of a repository are now at `/projects/<owner>/<repo>/-/settings`.
- Members who sign in with SSO can be disabled, but not removed, in Context7. Remove them in your identity provider.

### Added

- Added member management: administrators can change a member's role, disable or enable sign-in, and remove members who sign in with a password. Context7 does not let you demote, disable or remove the last active administrator.
- Added support for SAML 2.0 single sign-on for on-premise installations.
- Added a Google Drive connector, enabling ingestion and daily synchronization of Google Docs and Google Slides.
- Added a Notion connector that indexes approved pages and database rows and syncs them daily.

### Changed

- Redesigned the on-premise web interface. Repositories, Members, Usage and Settings are top-level tabs, and each settings section has its own page. A new parse queue page shows running, waiting and recent parses. A new repository settings page lets administrators change the branch, folders and exclusions of a repository.
- Updated the on-premise service image to run on Node.js 24 instead of Node.js 22.
- Improved the accuracy of APIDOC context by grounding endpoints within their respective page sections and dropping irrelevant snippets.
- Replaced the agent runtime that on-premise CodeDocs uses to write documentation.

### Fixed

- Fixed parser stalls that occurred when processing very large pages or long exclusion lists.
- Improved the stability of the on-premise CodeDocs agent by isolating its process and applying timeouts to SDK requests.
- Fixed an issue where large HTML conversion inputs could exhaust worker resources.
- Fixed issues with context7.json folder traversal and case-insensitive enterprise path guards.
- Fixed an issue that could lead to non-linear snippet token counting when processing looped AI outputs.

### Security

- Hardened security by binding GitLab tokens to exact hosts and restricting library import functionality to administrators only.
- Improved data privacy by masking secrets in on-premise queries before they are sent to Context7 Cloud.
- Enhanced data privacy by processing requests for restricted local libraries entirely on-premise, preventing their identifiers from being sent to Context7 Cloud.

</Update>

<Update label="2026-07-24" description="v1.3.0">

### Added

- Added library access control: restrict which libraries each user can query over the MCP server and the REST API, scoped to their single sign-on groups or to individual users, with a workspace-wide allow-by-default or restrict-by-default posture.
- Added namespace access rules that govern every library under a path, with rules on an individual library taking precedence over the longest matching namespace.
- Added an access audit log that records access-rule changes and blocked access attempts.
- Added support for running the on-premise image as multiple replicas behind a load balancer, backed by a shared PostgreSQL database and a shared vector store.

### Changed

- Improved reranking for queries with several requirements, and reduced duplicate snippets in responses.

</Update>
